# 内容质量与搜索外观参考

覆盖内容质量、E-E-A-T、排名系统、搜索外观元素、图片/视频 SEO、Core Web Vitals。

## 1. 内容质量评估

### 自我评估清单（"用户至上"标准）

**内容和质量：**
- [ ] 是否提供原创信息、报告、研究或分析？
- [ ] 对主题是否有实质性、完整、全面的描述？
- [ ] 是否提供深刻的见解，而非简单总结？
- [ ] 借鉴其他来源时是否提供了实质性额外价值？
- [ ] 标题是否实用、描述性（非夸大或耸人听闻）？
- [ ] 读者会收藏、分享或推荐此内容吗？
- [ ] 相比同类搜索结果，是否有实质性优势？
- [ ] 制作是否精良（无拼写/样式错误）？

**专业知识：**
- [ ] 呈现方式是否值得信任（明确来源、专业知识证据、作者介绍）？
- [ ] 网站是否被认为是该主题的权威？
- [ ] 内容是否由专家或资深爱好者撰写或审核？
- [ ] 是否存在可轻松验证的事实错误？

### 以搜索引擎为中心的警示信号

如果存在以下迹象，说明在为搜索引擎而非用户创作：
- 内容主要为吸引搜索流量而制作
- 大量生产不同主题的内容，寄希望于某些会成功
- 广泛使用自动化生产内容
- 主要总结他人观点而未增加价值
- 因话题流行而非读者需要而创作
- 读者读完后觉得需要再搜索才能获得更好信息
- 刻意凑字数
- 进入没有专业知识的领域
- 承诺回答实际上没有答案的问题
- 仅为了显得"很新"而更改日期或增删内容

### E-E-A-T 框架

Experience（经验）+ Expertise（专业性）+ Authoritativeness（权威性）+ Trust（可信度）

关键要点：
- **不是具体的排名因素**，但系统通过综合信号识别体现 E-E-A-T 的内容
- **可信度最重要**，其他三个维度影响可信度
- 不同内容侧重不同维度：一手体验内容靠经验，学术内容靠专业度
- YMYL（影响健康/财务/安全）主题需要最高水平的 E-E-A-T

## 2. AI 内容指南

### 可以使用 AI

- 研究主题、为原创内容添加结构
- 辅助写作（需人工把关准确性）

### 红线

- 使用 AI **规模化生成**无附加值的页面 → 违反"滥用规模化内容"政策
- AI 内容不豁免垃圾政策

### 三原则

1. 确保内容符合搜索要素和网络垃圾政策
2. 注重准确性、质量和相关性（含标题、描述、结构化数据、图片 alt）
3. 提供背景信息（披露 AI 使用情况有助于建立信任）

### 电商特殊要求

- AI 生成的图片：IPTC 元数据标记 `DigitalSourceType = TrainedAlgorithmicMedia`
- AI 生成的商品数据（名称/说明）：单独标记

## 3. 搜索外观元素

### 3.1 标题链接 (`<title>`)

| 规则 | 说明 |
|------|------|
| 每页唯一 | 不使用统一标题 |
| 描述性、简洁 | 避免"首页""个人资料"等模糊描述 |
| 不堆砌关键词 | 不重复相同词语 |
| 不重复样板文字 | 每页标题独一无二 |
| 可含品牌名 | 放在末尾，用分隔符隔开 |
| 主要标题明确 | 使用 `<h1>` + 更大字体 |
| 语言一致 | 与页面主要语言一致 |

### 3.2 摘要 (Snippet)

Google 从页面内容或 meta description 自动生成摘要。

优化方法：
- 每页编写独特的 meta description
- 包含页面关键信息（新闻含作者/日期，产品含价格/制造商）
- 高质量描述：具体、详细、有信息量
- 程序化生成：对数据库驱动网站，使用页面级数据自动生成

控制摘要的标记：
- `nosnippet`：彻底禁止摘要
- `max-snippet:[n]`：限制最多 n 个字符
- `data-nosnippet`：排除页面特定部分

### 3.3 网站图标 (Favicon)

要求：
- 方形，宽高比 1:1，≥8×8px（建议 ≥48×48px）
- URL 稳定（不频繁更改）
- Googlebot-Image 和 Googlebot 必须能访问
- 每个主机名一个图标
- 不含不当内容（色情/仇恨符号 → 被替换为默认图标）

### 3.4 网站名称

在首页添加 WebSite 结构化数据：
```json
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "首选名称",
  "alternateName": ["备选1", "备选2"],
  "url": "https://example.com/"
}
```

要求：
- 名称简明易懂，不使用冗长的法律实体名
- 避免通用名称（"XX市最佳牙医"不会入选）
- 结构化数据中的名称与其他来源一致
- 仅网域/子网域级（不支持子目录）

### 3.5 站内链接 (Sitelinks)

自动生成，无法手动控制。优化方式：
- 标题信息丰富、相关、精简
- 创建合理清晰的网站结构
- 从其他相关页面链接到重要页面
- 内部链接锚文本简明扼要

### 3.6 署名日期

三种提供方式：
1. 网页上的可见日期 + 明确标注
2. `Article`/`BlogPosting` 结构化数据的 `datePublished`/`dateModified`
3. 两者保持一致

规则：
- 必须是发布或更新日期（非未来日期，非内容中描述的事件日期）
- 减少页面上的其他日期以降低混淆
- 不要仅为了显"新"而改日期不更新内容

## 4. 图片 SEO

### 技术要求

- 使用 HTML `<img>` 元素（CSS 背景图片不被索引）
- 支持格式：BMP、GIF、JPEG、PNG、WebP、SVG、AVIF
- 自适应图片：使用 `<picture>` 或 `srcset`，始终提供 `src` 回退
- 用图片站点地图提交 CDN 上的图片 URL

### Alt 文本最佳实践

```
差：<img src="puppy.jpg"/>  （无 alt）
差：<img src="puppy.jpg" alt="puppy dog baby dog pup dog"/>  （堆砌）
好：<img src="puppy.jpg" alt="Dalmatian puppy playing fetch"/>  （描述性）
```

### 指定页面首选图片

按推荐顺序：
1. `primaryImageOfPage` schema.org 属性
2. `mainEntity.image`
3. `og:image` meta 标记
4. 结构化数据中的 `image` 字段

建议：选择与内容相关、有代表性的图片，避免通用 logo 或文字密集图。

### 其他

- 文件名描述性：`my-new-black-kitten.jpg` > `IMG00023.JPG`
- 安全搜索：露骨图片的页面需适当标记
- 可使用 `max-image-preview:large` 允许大图预览

## 5. 视频 SEO

### 发现与索引要求

- 使用标准 HTML 嵌入：`<video>`、`<embed>`、`<iframe>` 或 `<object>`
- 不使用 URI 片段加载视频
- 每个视频有独立观看页面
- 缩略图 URL 稳定
- 支持格式：3GP、MP4、WebM、MOV 等

### 视频功能

| 功能 | 要求 |
|------|------|
| 视频预览 | 允许提取视频文件，用 `max-video-preview` 控制时长 |
| 重要时刻 | 自动检测或使用 Clip/SeekToAction 结构化数据手动标记 |
| 直播标记 | BroadcastEvent 结构化数据 + Indexing API |
| 缩略图 | poster 属性 + 站点地图 `<video:thumbnail_loc>` + 结构化数据 `thumbnailUrl` |

### 移除视频

- 返回 404 或添加 noindex
- 使用结构化数据的 `expires` 属性
- 按地区限制：`regionsAllowed` 或 `<video:restriction>`

## 6. 精选摘要 (Featured Snippets)

- 无法手动标记，Google 自动判断
- 点击精选摘要会自动滚动到页面中的对应部分
- 一项内容成为精选摘要后不会在搜索结果首页重复显示

屏蔽方式：
- `nosnippet`：同时屏蔽精选摘要和常规摘要
- `max-snippet` 设为很小值：降低成为精选摘要的概率
- 绝对禁止：使用 `nosnippet`

## 7. Core Web Vitals

### 三大指标

| 指标 | 衡量 | 良好标准 |
|------|------|---------|
| LCP (Largest Contentful Paint) | 加载性能 | ≤ 2.5 秒 |
| INP (Interaction to Next Paint) | 交互响应 | ≤ 200 毫秒 |
| CLS (Cumulative Layout Shift) | 视觉稳定性 | < 0.1 |

### 网页体验自我评估

- [ ] Core Web Vitals 达标
- [ ] HTTPS 安全部署
- [ ] 移动设备显示效果良好
- [ ] 无过多分散注意力的广告
- [ ] 无干扰性插页式广告（全页覆盖广告）
- [ ] 用户能轻松区分主内容和辅助内容

### 插页式广告规则

- 不使用全页插页式广告遮挡内容
- 不将用户重定向到单独页面来征得同意
- 法定要求的插页（如年龄验证）：确保内容与广告重叠，让 Googlebot 不触发年龄限制也能抓取

### 重要说明

- 网页体验不是单一排名因素，而是多方面的综合评估
- 体验不佳时 Google 仍会尽可能展示最相关内容
- 有多个同样相关的内容时，体验好的才有优势

## 8. Google 排名系统关键概念

### 重要系统

| 系统 | 对 SEO 的启示 |
|------|-------------|
| BERT / 神经匹配 / RankBrain | 自然写作，不堆砌关键词，系统理解概念关联 |
| 段落排名 | 特定段落可独立被排名 |
| 原创内容系统 | 优先展示原创内容 |
| 可靠信息系统 | E-E-A-T 很重要 |
| 网站多元化 | 通常同一网站不超过 2 个结果 |
| 重复信息删除 | 避免大量相似/重复页面 |
| 完全匹配网域 | 不要为关键词注册域名 |
| 更新系统 | 时效性查询需要新鲜内容 |

### 核心更新

- 定期发布，在[搜索状态信息中心](https://status.search.google.com/)公布
- 排名下降：先等更新完成 → 再等至少一整周 → 然后分析数据
- 小幅下降（第 2→第 4 位）不需重大措施
- 大幅下降（第 4→第 29 位）需要全局自我评估
- 改进可能需要**几个月**才能体现
- 不一定要等到下一次核心更新来验证改进

### 网络垃圾更新

- SpamBrain（AI 垃圾检测系统）自动运行
- 移除垃圾链接后，之前获得的排名优势不会恢复

### 评价系统

奖励由专家/爱好者撰写的、含深入分析和原创研究的评价。适用于第一方独立评价内容。

## 9. Google 探索 (Discover)

- 被索引且符合政策的内容**自动有资格**显示
- 不需要特殊标记或结构化数据

优化重点：
- 标题准确反映内容要旨（非点击诱饵）
- 高品质图片：宽度 ≥ 1200px，>30 万像素，16:9
- `max-image-preview:large`
- 及时引人入胜的内容
- 良好的总体网页体验

**不适合**：职位申请、请愿书、表单、代码库、讽刺内容。

## 10. AI 搜索功能（AI 概览/AI 模式）

- **不需要特殊优化**或特殊标记
- 使用 `nosnippet`、`data-nosnippet`、`max-snippet`、`noindex` 可以控制
- 在 Search Console 效果报告的"网页"搜索类型下统计
- 做好基础 SEO + 独特深度的内容 = 最好的 AI 优化

## 11. 网络故事 (Web Stories)

- 必须是有效的 AMP 页面
- 必须是自己的规范网页
- 封面海报：≥640×853px，3:4 宽高比
- 每页文字：约 280 字符以内
- 标题：90 字符以内
- 视频每页：≤15 秒（最长 60 秒）
- 必须有叙事结构，非单纯宣传

## 12. 翻译搜索结果

- 默认启用，Google 自动翻译标题链接和摘要
- 禁用：`<meta name="robots" content="notranslate">`
- 广告网络运营方需要特殊处理广告投放

## 13. Signed Exchange (SXG)

用于在支持浏览器中显示自己的 URL（而非 Google AMP 缓存 URL）：
- 设置适当失效期
- 将个性化内容迁移到延迟加载元素
- 采用自适应设计
