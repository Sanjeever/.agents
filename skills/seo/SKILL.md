# Google 搜索 SEO 技能

本技能基于 Google Search Central 官方文档提炼，为 AI Agent 提供可执行的 SEO
诊断、优化和排查指导。面向网站开发者、SEO 从业者和内容创建者使用的场景。

## 核心原则（执行任何 SEO 任务前必须理解）

1. **区分三个独立环节**：Google 能否**抓取**（robots.txt、服务器可达性）→
   能否**索引**（noindex、内容质量、重复内容）→ 是否**选择展示**（排名、查询相关性）。
   三者互不包含，必须分别诊断。
2. **不承诺排名保证**。Google 排名由数百个因素自动决定，无人能保证特定排名。
3. **不使用欺骗手段**：不伪装内容、不隐藏文字/链接、不创建门页、不买卖链接、
   不使用规模化机器生成内容。违反者可能被从索引中彻底移除。
4. **结构化数据必须与页面可见内容一致**，不得标记用户看不到的信息。
5. **以用户价值为核心**：内容应为用户而写，非为搜索引擎而写。
6. **Google 搜索完全免费**，不存在付费提交或付费排名。
7. **变更生效需要时间**：从几天到几个月不等，一般至少等待数周再评估效果。

## 快速判断用户 SEO 需求类型

当用户提出 SEO 相关问题时，按以下优先级分类：

1. **站点完全不被收录** → 先检查技术可索引性（服务器状态码、robots.txt、noindex）
2. **部分页面不被收录** → 检查抓取预算、内部链接、内容质量、规范化
3. **收录但排名差** → 检查内容质量、E-E-A-T、结构化数据、网页体验
4. **流量突然下降** → 先区分是算法更新、技术故障、安全问题还是季节性波动
5. **搜索结果外观问题** → 检查标题/摘要/结构化数据/站点图标
6. **电商/国际化专项** → 检查商品结构化数据、Merchant Center、hreflang
7. **迁移/改版** → 检查重定向、站点地图、规范化、新旧站验证

## 工作流 1：技术 SEO 审计流程

```
用户请求技术 SEO 审计
│
├─ 1. 可索引性基础检查（见 references/technical-seo.md §1）
│   ├─ robots.txt 是否误屏蔽重要内容？
│   ├─ 重要页面是否返回 HTTP 200？
│   ├─ noindex 是否被误用？
│   └─ 内容是否以 HTML 文字形式存在（非纯 JS 渲染）？
│
├─ 2. 抓取效率检查（见 references/technical-seo.md §2-3）
│   ├─ 站点地图是否存在且提交到 Search Console？
│   ├─ 内部链接是否使用标准 <a href> 而非 JS 导航？
│   ├─ 是否有孤立页面（无任何内部链接指向）？
│   └─ 资源文件（CSS/JS/图片）是否被 robots.txt 误屏蔽？
│
├─ 3. 规范化检查（见 references/technical-seo.md §4）
│   ├─ 是否存在大量重复内容（www/非 www、HTTP/HTTPS、参数变体）？
│   ├─ canonical 标记是否正确且自引用？
│   ├─ 重定向链是否过长（>3 跳）？
│   └─ 站点地图中的 URL 是否都是规范 URL？
│
├─ 4. HTTPS 和移动端（见 references/crawling-indexing.md §2-3）
│   ├─ HTTPS 是否全面部署（含 HSTS）？
│   ├─ 移动端内容是否与桌面端等价？
│   └─ Core Web Vitals 是否达标？
│
└─ 5. 输出审计报告（按优先级列出问题）
```

## 工作流 2：抓取与索引问题排查

```
用户报告页面不被收录
│
├─ 步骤 1：用 Search Console 网址检查工具测试
│   ├─ 查看"网页索引编制"报告状态
│   ├─ 检查是否被 robots.txt 屏蔽
│   ├─ 检查 Googlebot 收到的 HTTP 状态码
│   └─ 查看渲染后的页面截图
│
├─ 步骤 2：按问题类型分支
│   ├─ robots.txt 屏蔽 → 修改 robots.txt，允许抓取后提交审核
│   ├─ noindex 存在 → 确认是否需要 noindex；如不需要则移除
│   ├─ 4xx/5xx 错误 → 修复服务器/应用问题
│   ├─ soft 404 → 返回真实 404/410 或补充内容
│   ├─ 内容质量低 → 改进内容至"实用、可靠、以用户为中心"
│   ├─ JS 渲染问题 → 检查动态渲染或 SSR 方案
│   └─ 已索引但不展示 → 检查查询相关性、排名因素
│
├─ 步骤 3：加速收录
│   ├─ 少量 URL：用网址检查工具请求重新抓取
│   └─ 大量 URL：更新并重新提交站点地图
│
└─ 详细排查步骤见 references/technical-seo.md 和 references/crawling-indexing.md
```

## 工作流 3：内容质量和页面优化流程

```
用户请求内容/页面 SEO 优化
│
├─ 1. 内容质量自评（详见 references/content-search-appearance.md §1-2）
│   ├─ 是否提供原创信息、分析或深度见解？
│   ├─ 标题是否准确描述内容（非夸大/耸人听闻）？
│   ├─ 与搜索结果中其他同类网页相比是否有实质性价值？
│   ├─ 是否展示可信度证据（作者背景、来源引用、专业知识）？
│   └─ 是否是"为用户而写"而非"为搜索引擎而写"？
│
├─ 2. 页面元素优化
│   ├─ <title>：每页唯一、描述性、简洁（见 references/content-search-appearance.md §3）
│   ├─ meta description：独特、信息丰富、引导点击
│   ├─ 标题层次：清晰语义结构（h1 → h2 → h3）
│   ├─ 图片：描述性文件名 + 有意义的 alt 文本 + 高品质
│   ├─ 视频：独立观看页面 + 结构化数据
│   └─ 结构化数据：按页面类型规划（见 references/structured-data.md）
│
├─ 3. 网页体验检查（见 references/content-search-appearance.md §7）
│   ├─ Core Web Vitals：LCP ≤ 2.5s, INP ≤ 200ms, CLS < 0.1
│   ├─ HTTPS 部署
│   ├─ 移动端适配（自适应设计优先）
│   └─ 无干扰性插页式广告
│
└─ 4. AI 生成内容注意
    ├─ 使用 AI 生成内容本身不违规
    ├─ 但规模化生成无附加值内容 → 违反垃圾政策
    └─ 建议披露 AI 使用情况以建立信任
```

## 工作流 4：结构化数据规划与校验流程

```
用户需要结构化数据建议
│
├─ 1. 确定页面类型和可用的富媒体搜索结果
│   ├─ 文章/博客 → Article / BlogPosting
│   ├─ 商品页 → Product + Review + Offer
│   ├─ 本地商家 → LocalBusiness + Organization
│   ├─ 食谱 → Recipe
│   ├─ 活动 → Event
│   ├─ 视频 → VideoObject
│   ├─ FAQ（仅限权威网站）→ FAQPage
│   ├─ 面包屑导航 → BreadcrumbList（几乎所有页面都适用）
│   └─ 更多类型见 references/structured-data.md
│
├─ 2. 实施检查清单
│   ├─ 使用 JSON-LD 格式（推荐），放在 <head> 中
│   ├─ 所有必需属性已填写
│   ├─ 尽可能填写建议属性
│   ├─ 标记内容与用户可见内容完全一致
│   ├─ 不使用 data-vocabulary.org（已废弃）
│   └─ 用富媒体搜索结果测试工具验证
│
├─ 3. 常见错误排查
│   ├─ robots.txt 屏蔽了 JS/CSS → 结构化数据渲染可能受影响
│   ├─ 标记了用户看不到的信息 → 违反政策
│   ├─ 缺少必需属性 → 无法显示富媒体结果
│   ├─ 列表页标记了商品详情页才该有的标记 → 叶级内容原则
│   └─ 动态注入的标记与页面 HTML 中的不一致
│
└─ 4. 验证和监控
    ├─ 使用 Search Console "富媒体搜索结果"报告
    ├─ 关注错误和警告数变化
    └─ 修复后请求重新抓取
```

## 工作流 5：搜索结果呈现优化流程

```
用户希望优化搜索外观
│
├─ 1. 标题链接优化
│   ├─ 每页 <title> 唯一且描述性
│   ├─ 避免关键字堆砌和样板文字
│   └─ 可包含品牌名，用分隔符隔开
│
├─ 2. 摘要优化
│   ├─ 编写独特的有吸引力的 meta description
│   └─ 或让 Google 自动从正文提取（有时更匹配查询）
│
├─ 3. 视觉元素
│   ├─ 网站图标（favicon）：48x48+ 方形，稳定 URL，可被抓取
│   ├─ 网站名称：首页添加 WebSite 结构化数据
│   └─ 站内链接：通过清晰的网站结构和内部链接让 Google 自动生成
│
├─ 4. 富媒体搜索结果资格
│   ├─ 部署相关结构化数据（见 references/structured-data.md）
│   ├─ 检查 Search Console 富媒体搜索结果报告
│   └─ 注意：标记正确也不保证展示
│
└─ 5. 控制不想展示的内容
    ├─ 用 nosnippet 禁止显示摘要
    ├─ 用 max-snippet 控制摘要长度
    ├─ 用 data-nosnippet 排除页面特定部分
    └─ 用 notranslate 禁止翻译
```

## 工作流 6：电商网站 SEO 检查流程

```
用户请求电商 SEO 诊断
│
├─ 1. 网站结构（见 references/ecommerce-international.md §1）
│   ├─ 从首页→类别→子类别→商品详情页的链接路径是否完整？
│   ├─ 搜索框不能替代导航链接（Googlebot 不提交搜索表单）
│   ├─ 分页是否使用 <a href> 链接（每页唯一 URL）？
│   └─ 无限滚动是否提供分页后备方案？
│
├─ 2. 商品 URL 结构
│   ├─ 使用描述性路径（/product/name）而非纯 ID（/product/3243）
│   ├─ 每个款式/规格有独立 URL
│   ├─ 过滤/排序参数用 robots.txt 或 noindex 管理
│   └─ 所有可索引页面使用自引用 canonical
│
├─ 3. 结构化数据
│   ├─ Product + Offer（含 price、availability）+ Review
│   ├─ BreadcrumbList（面包屑导航）
│   ├─ Organization（含 logo）
│   └─ ProductGroup（多款式管理）
│
├─ 4. Merchant Center
│   ├─ 注册并上传商品 Feed（"Google 购物"标签页必需）
│   ├─ 结构化数据与 Feed 数据保持一致
│   └─ 大型网站用 Content API 实时更新
│
└─ 5. 内容策略
    ├─ 原创商品说明（非复制制造商提供的内容）
    ├─ 深度评价（专家/爱好者撰写，含一手证据）
    └─ 交易信息清晰（退货政策、配送政策、客服渠道）
```

## 工作流 7：国际化网站 hreflang/canonical 检查流程

```
用户有多语言/多区域网站
│
├─ 1. 网址结构确认（见 references/ecommerce-international.md §2）
│   ├─ 推荐：不同 URL 区分语言/区域
│   │   ├─ ccTLD（example.de）— 地理定位最明确
│   │   ├─ 子域名（de.example.com）— 易设置
│   │   └─ 子目录（example.com/de/）— 维护成本低
│   └─ 不推荐：URL 参数、Cookie 动态调整、IP 嗅探
│
├─ 2. hreflang 检查
│   ├─ 每个语言版本列出自身及所有其他版本
│   ├─ 必须有返回链接（双向确认）
│   ├─ 语言代码用 ISO 639-1，区域用 ISO 3166-1 Alpha 2
│   ├─ 提供 x-default 备选页面
│   └─ 三种实现方式：HTML <link>、HTTP 标头、站点地图
│
├─ 3. 规范化协同
│   ├─ hreflang + canonical 指向同一域内的规范 URL
│   ├─ 同一语言的多区域变体（en-US vs en-GB）各自独立 hreflang
│   └─ 不互指的 hreflang 标记会被忽略
│
├─ 4. 常见错误
│   ├─ 缺少返回链接
│   ├─ 语言代码格式错误（如只用 "EN" 而非 "en" 或 "en-US"）
│   ├─ 使用无效区域代码（"UK"→应为"GB"；"EU" 无效）
│   └─ Googlebot 不设置 Accept-Language 标头
│
└─ 5. 语言区域自适应网页的特殊处理
    └─ 根据 IP/浏览器自动切换内容的网站 → Googlebot 默认 IP 在美国，
       可能无法抓取到其他语言版本 → 应提供单独的 URL 方案
```

## 工作流 8：Search Console 数据解读和问题定位流程

```
用户需要分析 Search Console 数据或排查流量问题
│
├─ 1. 流量下降分析（详见 references/monitoring-debugging.md §2）
│   ├─ 将时间范围扩展至 16 个月 → 排除季节性波动
│   ├─ 按搜索类型拆分（网页/图片/视频/新闻）
│   ├─ 确认是否有算法更新（检查 Google 搜索状态信息中心）
│   ├─ 区分：全站下降 vs 部分页面下降
│   └─ 用 Google 趋势判断是行业趋势还是自身问题
│
├─ 2. Search Console 关键报告解读
│   ├─ "效果"报告：展示次数、点击次数、CTR、平均排名
│   ├─ "网页索引编制"报告：已索引/未索引页面及原因
│   ├─ "抓取统计信息"报告：Googlebot 访问频率和主机状态
│   ├─ "富媒体搜索结果"报告：结构化数据错误/警告
│   ├─ "核心网页指标"报告：Core Web Vitals 达标情况
│   ├─ "人工处置措施"报告：是否受到人工惩罚
│   └─ "安全问题"报告：恶意软件/钓鱼/被黑检测
│
├─ 3. 气泡图分析（CTR × 排名）
│   ├─ 低排名 + 高 CTR → 重点优化目标（用户需要但找不到你）
│   ├─ 高排名 + 低 CTR → 优化标题和描述
│   └─ 低排名 + 低 CTR → 区分是否与网站相关后再决定
│
└─ 4. 搜索运算符辅助排查
    ├─ site:example.com → 查看已索引的页面
    ├─ site:example.com keyword → 查找特定关键词的索引页面
    └─ site:example.com viagra casino → 查找可能的垃圾内容
```

```markdown

[一句话概述问题和影响范围]

## 发现的问题

### 🔴 高优先级（影响索引/收录）
| # | 问题 | 证据 | 影响范围 | 建议改动 | 验证方法 |
|---|------|------|---------|---------|---------|

### 🟡 中优先级（影响排名/展示）
| # | 问题 | 证据 | 影响范围 | 建议改动 | 验证方法 |
|---|------|------|---------|---------|---------|
| 1 | 缺少 Product 结构化数据 | 富媒体搜索结果报告 | 所有商品页 | 添加 JSON-LD Product 标记 | 富媒体搜索结果测试工具 |

### 🟢 低优先级（优化建议）
| # | 问题 | 建议改动 | 验证方法 |
|---|------|---------|---------|
| 1 | 图片缺少 alt 属性 | 添加描述性 alt | 用 Lighthouse 审计 |

## 预期效果和时效
- 修复高优先级问题后，预计 X 天/周内可见索引改善
- 内容质量改进可能需要数周至数月
- 建议 X 周后复查以下指标：...
```

## 网络垃圾政策红线速查

以下行为可能导致网站被从搜索结果中**完全移除**：

| 行为 | 典型表现 |
|------|---------|
| 伪装真实内容 | 对 Googlebot 和用户返回不同内容 |
| 滥用门页 | 创建大量几乎相同的页面只为覆盖搜索查询 |
| 关键词堆砌 | 不自然地大量重复关键词 |
| 垃圾链接 | 买卖链接、过度交换链接、自动化链接 |
| 抄袭/爬取 | 复制他人内容无实质性附加值 |
| 滥用规模化内容 | 用 AI/自动化大量生成无价值页面 |
| 恶意软件/欺骗 | 植入恶意代码、钓鱼攻击、欺诈 |
| 滥用网站声誉 | 在权威网站托管第三方垃圾内容 |
| 隐藏文字/链接 | 白底白字、font-size:0、CSS 移出视口 |
| 欺骗性重定向 | 搜索引擎看到的内容与用户被重定向到的不一致 |

正常行为不违规：折叠式内容（手风琴）、幻灯片、仅屏幕阅读器可见文字、
付费链接使用 `rel="nofollow"` 或 `rel="sponsored"`、网站迁移和 A/B 测试。

## 重要概念区分速查

| 概念 | 作用机制 | 误用后果 |
|------|---------|---------|
| **robots.txt Disallow** | 阻止抓取，不阻止索引 | 被屏蔽的页面仍可能出现在搜索结果中（无摘要） |
| **noindex** | 阻止索引和展示 | 必须允许抓取才能看到 noindex 规则 |
| **canonical** | 指定规范 URL（信号，非指令） | Google 可能选择不同的规范 URL |
| **301 重定向** | 永久迁移，传递信号到新 URL | 链过长（>5 跳）会被截断 |
| **站点地图** | 辅助发现 URL，不保证索引 | 包含非规范 URL 会混淆信号 |
| **hreflang** | 指定语言/区域版本 | 缺少返回链接则标记被忽略 |
| **结构化数据** | 启用富媒体搜索结果资格 | 标记不可见内容违反政策 |

## 不纠结的事项（常见的 SEO 误区）

以下因素对 Google 排名**没有或极低**影响，不要在这些上面浪费时间：
- 元关键字（meta keywords）— Google 完全不使用
- 内容长度有"最佳标准" — 没有
- 子域名 vs 子目录哪个好 — 对业务有意义即可
- TLD 直接影响排名 — 仅在特定国家/地区定位时略有影响
- E-E-A-T 是具体排名因素 — 不是。系统通过综合因素间接体现
- 重复内容有"惩罚" — 没有人工处置（但抄袭他人内容除外）
- 创建 LLMs.txt 或特殊 AI 文件 — Google 不会特殊对待
- 为 AI 专门改写写作风格 — 不需要
- 分块（chunking）内容 — Google 系统能理解多主题页面
