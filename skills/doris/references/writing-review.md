# Doris 文档写作与审查

## 核心原则

从用户视角写作和审查：用户读完页面后，应知道该功能是什么、何时使用、如何运行、需要哪些前置条件、预期结果是什么，以及哪些限制或失败模式需要关注。

## 常见页面类型

### 概念或概览页

适用于架构、产品能力、表模型或功能介绍。

应包含：

- 一段简短概述。
- 存在多个选择时，给出按场景选型的指导。
- 在操作步骤之前解释核心概念和术语。
- 用能力矩阵或限制矩阵做对比。
- FAQ 只用于消除用户很可能产生的困惑。

### 任务或功能指南

适用于导入、部署、表设计、Catalog 创建、查询加速、连接器配置和运维管理。

应包含：

- 概述：功能做什么、何时使用。
- 前置条件：环境、权限、表结构、外部系统、必要配置。
- 快速上手：最小可运行的端到端流程。
- 参数/选项参考：类型、是否必填、默认值、作用、约束。
- 示例：常见场景和代表性变体。
- 验证：如何确认操作成功。
- 故障排查/注意事项：已知错误、限制、版本相关行为。
- 最佳实践：何时选择或避免该功能。

### SQL 函数参考

必需章节按以下顺序出现：

1. `描述`
2. `语法`
3. `参数`
4. `返回值`
5. `示例`

如果能澄清行为，可以增加 `别名`、`使用说明` 或 `注意事项` 等章节。

检查项：

- 描述用一段简洁文字说明函数作用。
- 如果 NULL 行为影响语义，应在描述或返回值中说明。
- 语法使用正式的 `sql` 代码块，覆盖所有重载或可选子句。
- 参数使用表格说明参数名、可接受类型、约束和可选性。
- 返回值说明返回类型，以及所有返回 NULL 的条件。
- 示例可运行，包含预期输出，并覆盖正常场景、重载或选项、边界行为和 NULL 输入。

### SQL 语句参考

典型章节：

- `描述`
- `语法`
- 当语句有 CTAS 类或模式相关变体时，增加变体语法。
- `必选参数`
- `可选参数`
- `权限控制`
- `注意事项`
- `示例`

对于 DDL、DML 和管理类语句，必须检查权限、不可逆影响、对象作用域，以及 internal 和 external catalog 之间的差异。

## Front Matter

使用简洁元数据：

- `title`：与主题匹配的页面标题。
- `language`：中文文档使用 `zh-CN`。
- `description`：对功能和价值的简短可搜索摘要。
- `keywords`：需要时包含产品术语、功能名和用户搜索词。
- `sidebar_label`：仅当侧边栏文字需要不同于标题时使用。
- `toc_min_heading_level` 和 `toc_max_heading_level`：仅在页面需要自定义目录层级时使用。

避免陈旧或误导性的描述。如果页面是参考文档，description 应具体而不是宣传化。

## 风格

- 统一使用 Doris 术语：FE、BE、Meta Service、Catalog、Database、Table、Tablet、Rowset、Compute Group、Stream Load、Broker Load、Routine Load、Group Commit、Async Materialized View。
- 功能文档优先使用“适用场景”“前置条件”“快速上手”“参数说明”“使用限制”“常见问题”“故障排查”等章节。
- 表模型使用 `DUPLICATE KEY`、`UNIQUE KEY`、`AGGREGATE KEY`，首次出现时解释中文名称。
- 语法块中的占位符使用尖括号，例如 `<table_name>`、`<catalog_name>`。
- SQL 示例使用 `sql` 代码块，输出使用 `text` 代码块。
- 示例注释保持简短，并服务于当前任务。
- 未经验证，不要声明默认值或版本支持。

## 按变更类型审查

### 文档内容

检查：

- 是否与邻近页面和活跃版本保持事实一致。
- 是否完整覆盖用户要完成的任务。
- 相对链接和锚点是否损坏。
- 标题层级和 front matter 是否正确。
- 示例和命令是否符合周边文档约定。
- 当同一功能预期在中英文或多版本保持一致时，镜像内容是否同步。

### 移动、重命名或删除

检查：

- sidebar 引用。
- 本地化副本。
- 活跃版本副本。
- redirect 行为。
- 来自 docs、community、blog 和配置的入站链接。
- 标题锚点变化。

### 前端、配置或构建变更

检查：

- Docusaurus 路由和插件行为。
- Hydration 安全性。
- 移动端和桌面端布局。
- 基础可访问性。
- SEO 相关元数据。
- 是否符合现有仓库模式。

## 常见值得指出的问题

- 函数页遗漏 NULL 行为或预期输出。
- 功能页只给命令，没有前置 DDL、权限或验证步骤。
- 页面把某个版本的行为描述成所有版本通用。
- 移动页面只更新 sidebar，没有同步链接、redirect 或本地化/版本副本。
- Catalog 或连接器页面遗漏必需属性、安全影响或外部系统限制。
- 部署页面遗漏端口、Java、网络、磁盘或高可用前置条件。
- 表设计页面推荐模型，但没有解释更新、聚合或查询权衡。
