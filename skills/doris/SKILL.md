# Doris

将此技能用于 Apache Doris 文档相关工作。内置参考资料是提炼后的指导，不是源文档摘录。使用本技能时不要直接引用或链接原始文档文件。

## 快速工作流

1. 先判断任务类型：
   - SQL 函数、SQL 语句、数据类型、操作符：读取 `references/sql-reference.md`。
   - 文档审查、内容结构、front matter、示例、语言或版本一致性：读取 `references/writing-review.md`。
   - 产品概念、系统架构、表设计、导入选型、查询加速、AI/检索定位：读取 `references/concepts.md`。
   - 安装部署、运维、故障排查、湖仓 Catalog、连接器、可观测性、管理任务：读取 `references/operations-reference.md`。
2. 写作或审查前，先明确用户目标和文档类型。
3. 优先保证用户可理解性，而不是堆砌实现细节。说明功能是什么、何时使用、前置条件、约束、示例和注意事项。
4. 如果精确行为、语法、版本支持或参数默认值很重要，而参考资料没有覆盖，应先检查当前仓库文档或代码再回答。
5. 做审查时，先给出具体问题；如果涉及本地文件，带上文件和行号。

## 文档审查清单

每次审查都要逐项回答适用的问题：

- 当前变更的目标是什么？实现是否真正满足该目标？
- 变更是否足够小、清晰、聚焦？
- 如果路径或导航发生变化，当前文档、活跃版本文档、本地化文档、sidebar、redirect 和配置引用是否一致？
- front matter、标题层级、锚点、示例、相对链接是否有效？
- 对 SQL 文档，必需章节是否按顺序出现？语法、NULL 行为、返回类型、示例和输出是否完整？
- 对功能文档，是否覆盖概述、快速上手、前置条件、参数/选项、示例、注意事项和最佳实践？
- 如果修改了前端、配置或构建文件，是否符合仓库约定，并保持桌面端和移动端行为正常？
- 哪些验证适用？实际运行了哪些，哪些没有运行？

## 写作规则

- 写中文文档时使用简体中文，并保持 Doris 术语一致。
- 示例要可运行且自包含。用户需要时，应提供建表 DDL、命令和预期输出。
- 明确说明版本相关行为。不要把依赖 Doris 版本、架构、表模型、Catalog 类型、会话变量或配置项的行为写成普遍行为。
- 参数、选项、类型映射、能力矩阵和场景选型优先使用表格。
- 只有涉及正确性、安全、数据丢失或运维风险时才使用警告。
- 避免大范围重写和无关格式变更。
