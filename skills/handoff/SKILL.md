# Handoff Skill

## 作用

当需求分析完成后，生成项目根目录下的 `handoff.md`。

`handoff.md` 用于下一次独立 Coding Agent
会话快速理解任务，不记录聊天过程，只记录可执行信息。

------------------------------------------------------------------------

## 使用方式

触发命令：

``` text
/handoff
```

------------------------------------------------------------------------

## 执行流程

### 1. 检查需求完整性

确认已有：

-   任务目标
-   实现范围
-   非目标范围
-   技术方案
-   验收标准

如果关键信息缺失，先询问，不生成文件。

------------------------------------------------------------------------

### 2. 检查代码仓库

读取项目结构，确认：

-   相关模块
-   已有实现
-   影响文件
-   技术栈
-   数据库结构（如涉及）

不要依赖聊天中的猜测。

------------------------------------------------------------------------

### 3. 生成 handoff.md

文件位置：

``` text
./handoff.md
```

内容必须包含：

``` md
# Handoff: <任务名称>

## 1. 任务摘要

简短描述本次任务。

## 2. 背景

说明当前状态、存在的问题以及修改原因。

## 3. 目标与范围

### 目标

列出需要实现的内容。

### 不包含

列出明确不处理的内容。

## 4. 技术上下文

描述：

- 项目架构
- 相关模块
- 技术约束
- 已确定的技术决策

## 5. 当前实现分析

列出已有代码：

| 文件 | 说明 |
|---|---|
| path | description |

## 6. 实现方案

描述：

- 新增文件
- 修改文件
- API 变化
- 数据库变化
- 配置变化

必须具体到文件和模块。

## 7. 文件影响范围

### 修改

已有文件。

### 新增

新建文件。

### 避免修改

无关模块。

## 8. 约束条件

记录：

- 兼容性要求
- 编码规范
- 禁止事项
- 已确定方案

## 9. 验收标准

使用 checklist：

- [ ] 功能完成
- [ ] 测试通过
- [ ] 文档同步

## 10. Agent 注意事项

记录：

- 易错点
- 特殊实现要求
- 关键上下文
```

------------------------------------------------------------------------

## 编写规则

### 只记录执行信息

不要写：

-   讨论过程
-   废弃方案
-   聊天记录
-   临时调试信息

只保留：

-   最终需求
-   最终决策
-   实现路径

------------------------------------------------------------------------

### 内容必须具体

错误：

``` md
优化用户模块。
```

正确：

``` md
修改：

backend/user/UserService.java

新增：

backend/user/cache/UserPermissionCache.java

增加用户权限缓存，TTL 10 分钟。
```

------------------------------------------------------------------------

### 保持范围边界

必须明确：

-   做什么
-   不做什么

避免新的 Coding Agent 自行扩大需求。

------------------------------------------------------------------------

## 输出要求

生成完成后：

1.  确认文件路径：

``` text
Created: ./handoff.md
```

2.  简短说明包含内容。

生成 `handoff.md` 后停止，不执行代码修改。
